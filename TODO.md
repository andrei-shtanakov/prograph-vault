## Правила ведения

- После выполненной задачи — маркер task-list `- [x]` (именно так, не голое `[x]`:
  парсер распознаёт пункт только как элемент списка) плюс номер PR / хеш коммита.
- Задача стала неактуальной — зачеркнуть `~~...~~` с пометкой **почему**, не удалять:
  дельта-счётчики читают исчезновение строки как «закрыто».
- Поля пункта — инлайн-теги `@owner:` / `@blocked_by:` / `@trigger:"…"`, все
  опциональны: пустое поле означает «неизвестно» и это честнее выдуманного значения.
- Блокер пишем **канонической** формой `@blocked_by:todo://<repo>/<id>` — она
  единственная порождает ребро в графе зависимостей. Форма `<repo>#<slug>` —
  переходная: остаётся legacy при любом написании, несёт только `legacy_blocker_ref`,
  не получает `resolved_target` и ребром не становится.
- `@id:<node-id>` — канонический идентификатор пункта (ADR-ECO-005 PF-2B): строчная
  грамматика `[a-z0-9][a-z0-9._-]{0,63}`, из него строится URI `todo://ecosystem-kb/<id>`.
  Каноническое имя репо — ключ манифеста `ecosystem-kb`; `prograph-vault` — это
  `git_dir`, локатор, а не идентичность.
- **Теги и суть пункта — на одной строке с `- [ ]`**: парсер разбирает пункт строго
  построчно и продолжений ниже не видит. Отступленные строки под пунктом — контекст
  для человека.
- Слаг принятого обязательства менять нельзя: он согласован с `@blocked_by` у соседа, и
  приёмка выводится из совпадения. Нужно другое имя — сначала правится ссылка у соседа.
