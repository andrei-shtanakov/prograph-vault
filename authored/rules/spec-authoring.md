# Подготовка спеки и плана: локальный цикл, один PR

Действует для док-стадий любой арки: дизайн-спека и план имплементации.
Решение владельца 2026-08-26. Мотив: стадийные PR (спека → план → правки
спеки → правки плана) множат платные прогоны гейта, минуты CI и хореографию
мержей, не добавляя качества — итерации ревью дешевле и быстрее локально,
подписочным Codex, чем через PR-циклы. Ревью при этом **не убирается**: те же
линзы переносятся в локальный контур, а финальную приёмку по-прежнему делает
один платный CI-прогон на готовой паре.

Чекпойнт владельца один: **готовая пара спека+план**. Промежуточных
PR-чекпойнтов на спеку и план по отдельности нет.

## Цикл

```
идея
→ (опционально) discovery
→ Claude Code пишет spec
→ Codex локально ревьюит spec
→ Claude Code исправляет spec
→ Codex повторно проверяет
→ spec converged
→ Claude Code пишет implementation plan
→ Codex проверяет пару spec + plan
→ Claude Code исправляет plan (и при необходимости spec)
→ повторное ревью пары
→ pair converged
→ draft PR
→ добавить номер PR в TODO/метаданные
→ ready for review
→ один платный CI-прогон
```

Локальный ревьюер — Codex CLI в соседнем терминале; в репо с
codex-review-гейтом можно гонять `sh scripts/review/local.sh` — та же линза
и порог, что у гейта, ноль долларов API.

## Два условия завершения — они разные

**Spec converged:**

- нет blocker/major-находок;
- нет нерешённых архитектурных вопросов и TBD;
- состояния ошибок и authority определены;
- интерфейсы и не-цели согласованы;
- ссылки и факты проверены по коду (якоря строк — скриптом, не глазами).

**Pair converged:**

- каждая нормативная часть спеки покрыта задачей плана;
- план не вводит решений, которых нет в спеке;
- порядок реализации сохраняет рабочее или явно описанное промежуточное
  состояние;
- тесты доказывают требования, включая fail-closed пути;
- команды проверки и границы репозиториев выполнимы.

## Возврат по находкам ревью пары

- **Архитектурный дефект** → процесс возвращается к спеке; после её
  стабилизации план перепроверяется **целиком**.
- **Замечание только об исполнении** → меняется план, полный spec-цикл не
  перезапускается.

## Ветка, коммиты, PR

Всё ведётся в одной ветке с понятными коммитами:

```
docs(spec): draft ...
docs(spec): address local architecture review
docs(plan): implementation plan ...
docs(plan): address local traceability review
```

Черновые промежуточные исправления — squash/amend локально; журнал PR для
них не нужен. PR один на пару: открывается **драфтом** уже сошедшимся, после
драфта номер PR вносится в TODO/метаданные тем же PR, снятие драфта — один
платный прогон гейта (экономный цикл из `git-workflow.md`, шаг 3). Находки
этого прогона отрабатываются в том же PR.

## Автоматизация (перспектива)

Disputatio впоследствии автоматизирует два вложенных цикла:

```
author ↔ spec reviewer
         ↓ converged
author ↔ spec-plan reviewer
         ↓ converged
       one PR
```

До этого правило исполняется вручную. Запрос продюсеру подан:
disputatio#44 (inbox-issue по ADR-ECO-006).
