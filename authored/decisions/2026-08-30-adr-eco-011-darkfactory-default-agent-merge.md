# ADR-ECO-011: DarkFactory — агентский мерж по умолчанию

**Статус:** **Accepted** (ратифицировано 2026-08-30, Andrei, в сессии devtools при
разборе конвейера inbox-оркестратора) · **Решает:** Andrei (единственный владелец
экосистемы)

**Скоуп:** кто мержит PR по умолчанию; как человеческий мерж подключается как опция;
где живёт политика; чем агентский мерж отличим от человеческого в записи.
**Вне скоупа:** триггеры автоматических прогонов; publish-фазы issue-runner
(отдельная спека); гранулярность коммитов и PR.

**Supersedes:** ADR-ECO-008 D1 в части интерактивной колонки («человек, всегда,
переопределения нет») — асимметрия по типу сессии снимается. Остальное тело
ADR-ECO-008 (D2 базовый слой, D4 сводка, D6 наблюдаемость как принцип) действует.

**Закрывает:** OQ-2 ADR-ECO-008 (окно ожидания — не вводится); блокер ввода D1 в
действие (замер I4 «агентский мерж записался бы человеческим») — решением D3 ниже.

**Связано:** [[2026-08-19-adr-eco-008-merge-authority-by-session-type]],
[[2026-08-19-adr-eco-008a-merge-broker-runtime]],
`authored/rules/git-workflow.md` (операционный текст),
решение владельца 2026-08-28 о терминальном ревью ai-prosto как дефолте.

---

## Причина

ADR-ECO-008 честно диагностировал: человеческий гейт мержа перестал производить
ревью и превратился в утверждение о контроле, которого нет. Но лекарство он выписал
только половине системы — автоматическим прогонам, оставив интерактивные сессии на
«человек, всегда». За прошедшие десять дней выяснилось, что асимметрия не держится:

- **Ревью-контур стал общим.** С 2026-08-28 дефолт всех PR — терминальное
  codex-ревью с публикацией вердикта от ai-prosto. Интерактивная сессия проходит
  тот же контур, что и прогон: approve/request-changes на PR, fingerprint-маркер,
  наследование вердикта. Основание для разного субъекта мержа исчезло — слой,
  реально ловящий дефекты, у обоих путей один.
- **Человеческий мерж в интерактиве выродился в «смержил» одним словом.** Владелец
  мержит по сигналу готовности, не читая диф (что ADR-ECO-008 уже признал), и
  каждый цикл ждёт этого слова. Узкое место осталось — контроль не прибавился.

Владелец формулирует курс явно: **DarkFactory** — конвейер, где мерж по умолчанию
делает агент, а человек подключается точечно и по объявленной конфигурации, а не
по умолчанию.

## Решение

### D1 — Дефолт: мержит агент, на обоих типах сессий

Право мержа перестаёт зависеть от типа сессии. По умолчанию PR мержит агент —
и в автоматическом прогоне, и в интерактивной сессии. Условия — прежние и
непререкаемые (ADR-ECO-008 D2 + шаг 3 git-workflow):

- включённое для репо ревью собрано, вердикт — **approve**; request-changes или
  неприбывшее ревью = `unknown` ⇒ мерж не выполняется, PR остаётся человеку;
- зелёные обязательные проверки; при неполных данных GitHub — fail-closed;
- **всегда человеку** (не переопределяется): PR по authority-root путям
  (ADR-ECO-004 I2); PR без предъявленного evidence базового слоя; репо с внешним
  upstream (self-merge невозможен).

После мержа агент выполняет и хвост: `--ff-only` подтяжка дефолтной ветки, удаление
влитой ветки в обеих половинах, prune.

### D2 — Человеческий мерж: настраиваемая опция, два уровня

`merge_policy` объявляется конфигурацией, а не выводится из обстоятельств:

- **Уровень экосистемы** — общий конфиг флота (SSOT: `ai-orchestrators-workspace`,
  как зонтик набора репо и пинов); поле `merge_policy = "agent" | "human"`,
  дефолт `agent`. Файл конфига — пререквизит арки issue-runner; его схема
  фиксируется там.
- **Уровень репо** — оверрайд строкой `Мерж: человек` в секции «Git workflow»
  CLAUDE.md конкретного репо (тот же механизм, что opt-in Copilot-ревью).

**Переходный период** (до появления экосистемного конфига): отсутствие объявления
читается как дефолт `agent`; репо, желающее человеческого мержа, объявляет это в
своём CLAUDE.md. Объявление `merge_authority` прогона (ADR-ECO-008 D5) остаётся
третьим, самым узким уровнем — прогон может ужесточить до `human`, но не ослабить
репо-оверрайд.

### D3 — Актор мержа: агент мержит от ai-prosto

Замер I4 блокировал ADR-ECO-008 D1 тем, что агентский мерж записался бы
человеческим. Решение — разнести акторов: **агентский мерж исполняется от учётки
ai-prosto** (профиль `~/.config/review`, тот же, что публикует ревью), человеческий
— от владельца. Поле `merged_by` на PR становится наблюдаемым различителем
agent/human без нового рантайма: аудит — `gh pr list --json mergedBy`.

Следствия: ai-prosto получает write-права в репо флота, где DarkFactory активен;
цепочка на PR читаема целиком — автор (сессия владельца) → ревью (ai-prosto,
вердикт с fp-маркером) → мерж (ai-prosto) — и каждая роль записана своим актором.
Steward-типы `agent_merge`/`human_merge` (ADR-ECO-008 D6) мапятся на `merged_by`
без эвристик. Ограничение GitHub «автор не аппрувит свой PR» не задевается: автор
PR — владельческая учётка.

### D4 — Окно ожидания не вводится (OQ-2 закрыт)

Сигнал готовности (сводка в описании PR, ADR-ECO-008 D4) уведомляет; окно ожидания
вернуло бы узкое место в мягкой форме. Человек, желающий пред-мержевого контроля в
конкретном репо, включает `Мерж: человек` — это и есть окно, но явное и адресное.

## Последствия

**Прописать (арка не закончена, пока не сделано):**

1. `authored/rules/git-workflow.md` — шаг 4 и заголовок правила (этим же PR);
2. `CLAUDE.md` репозиториев флота — заменить «мерж делает человек» на новый
   дефолт (devtools — зеркальным PR; остальные — волной по мере касания);
3. корневой CLAUDE.md воркспейса — зонтичная формулировка;
4. ai-prosto — write-права в репо флота (действие владельца в GitHub);
5. экосистемный конфиг с `merge_policy` — в спеке issue-runner.

**Чего решение НЕ даёт:** оно не запускает работу само (триггеры — отдельная арка)
и не ослабляет ревью-гейт — агент без approve не мержит ничего.

## Открытые вопросы

- **OQ-1.** Нужен ли для DarkFactory отдельный дашборд агентских мержей в
  dispatcher, или `merged_by`-аудита достаточно. Пока — достаточно; пересмотр при
  первом инциденте.
- **OQ-2.** Распространять ли D3 на автоматические прогоны 008a (merge broker
  сейчас проектировался под installation-токен) — решить в арке issue-runner.
